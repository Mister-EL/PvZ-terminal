# Запись и просмотр повторов

Повтор хранит seed, сценарий, сложность и нажатия игрока во времени симуляции. Его можно проиграть без терминального интерфейса и сравнить итоговую статистику.

## Записать партию

Запустите игру с каталогом для повторов:

```bash
python3 -m pvz --record-dir ./replays

# Короткая проверка: выживание с заданным seed, без записи рекордов
python3 -m pvz --survival --seed 71 --no-save --record-dir ./replays
```

Победа, поражение и обычный выход через Q сохраняют партию в новый JSON-файл. Имена файлов уникальны; существующие повторы не перезаписываются. Каталог создаётся при сохранении. Если путь недоступен, игра показывает ошибку и сохраняет уже существующие файлы.

Ctrl+C прерывает игру без сохранения текущего повтора. Для обычного завершения используйте Q.

Без явного `--seed` запись получает случайное зерно в выживании или зерно выбранного сценария. При записи допустимы seed от 0 до 2147483647.

`--no-save` выключает прогресс и рекорды, но оставляет запись повторов. Время в справке, на паузе и при слишком маленьком окне в повтор не добавляется.

## Проверить и проиграть файл

Из папки проекта:

```bash
python3 tools/replay.py validate ./replays/имя-файла.json
python3 tools/replay.py play ./replays/имя-файла.json
```

Обе команды выводят JSON и работают без интерактивного терминала. Они читают повтор, не изменяют его и не записывают результат в пользовательский прогресс. При ошибке команда пишет сообщение в stderr и возвращает код 2.

`validate` проверяет версию, поля, типы, пределы и порядок действий. Успешная проверка формата не означает победу. `play` запускает настоящую игровую логику и выводит результат партии:

- `outcome`: победа, поражение, выход, пауза или незавершённая игра;
- `elapsed`, `score`, `sun`: время, счёт и оставшееся солнце;
- `zombies_killed`, `plants_placed`, `plants_lost`: уничтоженные враги, посадки и потери;
- `lawnmowers_used`, `sun_generated`: потраченные косилки и заработанное солнце;
- `state_sha256`: отпечаток состояния поля, врагов, снарядов, курсора и перезарядок.

Для сравнения запусков используйте одну версию игры и одинаковые данные сценариев. Обновление баланса может изменить результат старого повтора. Один seed задаёт случайные события; действия игрока воспроизводятся из записи.

## Формат версии 1

В файле есть только `schema_version`, `seed`, `scenario`, `difficulty`, `duration` и `actions`. `scenario: null` означает выживание. Имена, контакты и сведения об аккаунте не нужны и не принимаются форматом.

Действия содержат `time` и `kind`. Для перемещения нужен `direction`, для выбора растения нужен `plant`. Поддерживаются `move`, `select`, `plant`, `dig`, `pause`, `resume` и `quit`. Несколько действий в один момент выполняются в порядке записи.

Время кратно 0,05 игровой секунды. Пауза и продолжение имеют одинаковое игровое время. После `quit` действий нет. Запись ограничена двумя часами симуляции, 100 000 действий и размером 8 МиБ.

Попытка посадить растение без денег записывается как обычное нажатие: при просмотре игра повторит отказ. Повтор не задаёт солнце, здоровье или расположение врагов напрямую.

## Примеры решений сценариев

В [каталоге](scenarios/README.md) лежат проверенные маршруты посадок для всех уровней. Файлы в `scenarios/solutions/` используют отдельный формат с координатами посадки. Они нужны тестам проходимости; `tools/replay.py` читает записи нажатий из `--record-dir`.

Для проверки игры и маршрутов:

```bash
python3 -m unittest discover -s tests -v
```
